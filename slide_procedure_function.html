01 · KONSEPSI & ARSITEKTUR Peralihan dari View ke Stored Routine

Kenapa Menaruh Logika Bisnis di Database?

Inti Perbedaan: View hanya menyimpan kueri SELECT untuk menampilkan data. Stored Routine menyimpan langkah kerja lengkap: ada percabangan IF, perulangan, variabel, dan bisa mengubah banyak tabel sekaligus.

Skenario Kasir Minimarket: Tiap transaksi butuh 4 langkah: (1) cek stok → (2) potong stok → (3) catat nota → (4) tambah poin member. Menaruh alur ini di database memberikan 4 keuntungan praktis:

01 Hemat Jaringan

Aplikasi kasir cukup kirim 1 perintah CALL, bukan bolak-balik kirim belasan kueri lewat jaringan WiFi/kabel.

02 Aturan Terpusat

Rumus diskon, batas stok, dan poin ditulis sekali di database. Aplikasi kasir, web, atau mobile memakai aturan yang seragam.

03 Cache Eksekusi

Kueri dikompilasi sekali di awal dan disimpan di memori server. Pemanggilan berikutnya langsung jalan tanpa parsing ulang.

04 Akses Lebih Aman

Kasir cukup diberi izin menjalankan prosedur (EXECUTE), tanpa izin langsung mengubah tabel master produk fisik.

02 · KOMPARASI UTAMA Stored Function vs Stored Procedure

Perbedaan Utama: Function vs Stored Procedure

Function (UDF) = Kalkulator: Diberi input data, menghitung, dan wajib mengembalikan tepat 1 nilai (RETURN). Dipakai di dalam kueri SELECT.
Procedure = Robot Kerja: Menjalankan serangkaian tugas nyata (misal: potong stok dan catat nota). Dipanggil terpisah dengan perintah CALL.
Kriteria User Defined Function (UDF) Stored Procedure
Nilai Kembalian Wajib 1 nilai skalar via klausa RETURNS & pernyataan RETURN. Tidak memiliki return langsung; mengembalikan nilai via parameter OUT / INOUT atau result set.
Cara Panggil Dipanggil di dalam kueri SQL biasa (SELECT fc_name(), WHERE fc_name() > 0). Dipanggil terpisah sebagai perintah mandiri: CALL sp_name(argumen);.
Ubah Data (DML) Dilarang mengubah isi tabel (INSERT/UPDATE/DELETE) saat dipanggil kueri baca. Bebas mengubah data, mengontrol transaksi (COMMIT/ROLLBACK), dan kueri dinamis.
Kapan Dipakai Perhitungan skalar, format teks (contoh: format rupiah), konversi nilai, atau nomor urut nota. Alur kerja transaksi multi-tabel, batch processing berkala, dan otomasi kasir.

03 · SINTAKS & UDF Karakteristik & Nilai Kembalian Tunggal

User Defined Function (UDF) & Alasan Butuh DELIMITER

UDF adalah fungsi buatan sendiri yang menghasilkan satu nilai dan dipanggil langsung di dalam kueri SELECT:

CONTOH: GENERATOR NOMOR NOTA OTOMATIS
DELIMITER $$ CREATE FUNCTION fcGenerateNoNota(tgl DATE) RETURNS CHAR(10) DETERMINISTIC READS SQL DATA BEGIN DECLARE tgl_prefix CHAR(6); DECLARE last_seq INT DEFAULT 0; SET tgl_prefix = DATE_FORMAT(tgl, '%y%m%d'); SELECT IFNULL(MAX(CAST(RIGHT(nonota, 4) AS UNSIGNED)), 0) INTO last_seq FROM nota WHERE LEFT(nonota, 6) = tgl_prefix; RETURN CONCAT(tgl_prefix, LPAD(last_seq + 1, 4, '0')); END$$ DELIMITER ; -- Contoh Pemanggilan di dalam SELECT: SELECT fcGenerateNoNota('2022-08-03') AS nota_baru;
Kenapa Butuh DELIMITER $$? Secara default MySQL menganggap titik koma (;) sebagai akhir perintah. Di dalam BEGIN...END terdapat banyak titik koma. Tanpa DELIMITER $$, MySQL akan berhenti sebelum seluruh fungsi selesai dibaca. Ibaratnya: titik koma adalah koma di dalam kalimat, sedangkan $$ adalah tanda selesai untuk satu cerita utuh.
LABEL Karakteristik Sifat Fungsi
  • DETERMINISTIC: Input sama pasti menghasilkan output yang selalu sama persis.
  • NOT DETERMINISTIC: Nilai kembalian bisa berubah walau inputnya sama (contoh: membaca fungsi waktu NOW()).
  • NO SQL: Murni perhitungan angka atau teks tanpa membaca tabel sama sekali.
  • READS SQL DATA: Membaca data tabel menggunakan SELECT tanpa mengubah isi tabel.

04 · PARAMETER PROCEDURE Aliran Data: IN, OUT, dan INOUT

Tiga Mode Parameter: Analogi Mesin Fotokopi

Analogi Mesin Fotokopi: IN = Dokumen asli masuk scanner (dibaca, aslinya tidak berubah) · OUT = Lembaran fotokopi keluar (diisi procedure, diambil pemanggil) · INOUT = Formulir pendaftaran masuk dicoret/diedit nilainya, lalu dibawa pulang. (Gunakan tanda @variabel untuk menampung hasil OUT/INOUT)
IN Input Saja (IN)

Mode bawaan (default). Nilai dikirim oleh pemanggil ke dalam procedure. Perubahan nilai di dalam procedure tidak akan mempengaruhi variabel di luar.

CREATE PROCEDURE spCek( IN p_kd CHAR(4) ) ...
OUT Keluaran Saja (OUT)

Nilai awalnya kosong (NULL). Procedure yang bertugas mengisi nilainya, lalu hasilnya dikirim balik ke variabel pemanggil.

CREATE PROCEDURE spGetInfo( OUT p_nama VARCHAR(50) ) ... CALL spGetInfo(@nm);
INOUT Bolak-Balik (INOUT)

Membawa nilai awal dari luar, diproses atau diubah nilainya di dalam procedure, lalu nilai barunya dikembalikan lagi ke pemanggil.

CREATE PROCEDURE spDiskon( INOUT p_hrg INT ) ... SET @hrg = 10000; CALL spDiskon(@hrg);

05 · KONTROL ALUR Percabangan & Perulangan di Blok BEGIN-END

Logika Alur: Percabangan & Perulangan

Logika Pemrograman di Database: Sama seperti di Python, Java, atau C++, Anda bisa menggunakan struktur IF dan Looping di MySQL. Bedanya, seluruh logika ini langsung dieksekusi di server database tanpa perlu keluar ke aplikasi.
CONDITIONAL IF-THEN-ELSE & CASE
-- Percabangan Bersyarat IF v_stok = 0 THEN SET status = 'HABIS'; ELSEIF v_stok < 10 THEN SET status = 'KRITIS'; ELSE SET status = 'AMAN'; END IF; -- Evaluasi Banyak Nilai dengan CASE CASE p_jenkel WHEN 'L' THEN SET label = 'Laki-laki'; WHEN 'P' THEN SET label = 'Perempuan'; ELSE SET label = 'Tidak Diketahui'; END CASE;
LOOPING LOOP, WHILE, & REPEAT
-- 1. LOOP dengan Label & LEAVE (Pemberhentian Eksplisit) my_loop: LOOP IF v_selesai = 1 THEN LEAVE my_loop; END IF; END LOOP my_loop; -- 2. WHILE (Uji Kondisi di Awal) WHILE v_counter < 10 DO SET v_counter = v_counter + 1; END WHILE; -- 3. REPEAT (Uji Kondisi di Akhir) REPEAT SET v_counter = v_counter + 1; UNTIL v_counter >= 10 END REPEAT;

06 · ITERASI PER BARIS Membaca dan Memproses Data Baris demi Baris

Cursor: Memproses Data Baris demi Baris

Analogi Membaca Lembar Absensi: Kueri SQL biasa langsung mengolah satu tabel sekaligus secara serentak. Cursor bekerja seperti dosen membaca lembar absensi: tunjuk nama pertama, baca datanya (FETCH), periksa atau beri nilai individual, lalu lanjut ke bawah sampai habis (v_selesai = 1).
CONTOH: CURSOR BONUS POIN CUSTOMER
-- 1. Deklarasi Cursor & Handler NOT FOUND DECLARE curCustomer CURSOR FOR SELECT kodecus, pointterkumpul FROM customer WHERE kodecus <> 'M0000'; DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_selesai = 1; -- 2. Membuka Cursor OPEN curCustomer; -- 3. Loop Pengambilan Baris per Baris bacaLoop: LOOP FETCH curCustomer INTO v_kode, v_poin; IF v_selesai = 1 THEN LEAVE bacaLoop; END IF; -- Logika evaluasi individual per baris customer UPDATE customer SET pointterkumpul = pointterkumpul + 10 WHERE kodecus = v_kode; END LOOP bacaLoop; -- 4. Menutup Memori Cursor CLOSE curCustomer;
SIKLUS 5 Langkah Menggunakan Cursor
  1. DECLARE CURSOR: Daftarkan kueri SELECT yang akan dibaca baris per baris.
  2. DECLARE HANDLER: Pasang penanda selesai (SET v_selesai = 1) saat FETCH mencapai baris terakhir.
  3. OPEN: Jalankan kueri dan siapkan penunjuk (pointer) data di memori.
  4. FETCH di dalam LOOP: Ambil 1 baris ke variabel lokal. Jika baris habis, hentikan loop dengan LEAVE.
  5. CLOSE: Tutup cursor dan bersihkan alokasi memori server.
Kapan Sebaiknya Dipakai? Cursor butuh memori dan waktu lebih banyak karena berjalan per baris. Kalau manipulasi data bisa diselesaikan dengan kueri biasa (UPDATE ... CASE), kueri biasa jauh lebih cepat dan disarankan.

07 · PENANGANAN ERROR Menjaga Integritas Transaksi & Validasi Input

Error Handling: Menjaga Transaksi Tetap Aman

SIGNAL 45000 = Satpam Toko: Jika pembeli memesan melebihi stok yang ada di rak, prosedur langsung membatalkan pesanan dan memberi pesan yang jelas. ('45000' adalah kode standar untuk pesan error buatan sendiri).
Transaksi ACID = Transfer ATM: Saldo berkurang dan penerima bertambah wajib sukses bersama (COMMIT). Jika koneksi mati di tengah jalan, semua perubahan dibatalkan utuh (ROLLBACK). Tidak boleh selesai separuh jalan.
CONTOH: VALIDASI STOK VIA SIGNAL
CREATE PROCEDURE spPotongStok( IN p_kd CHAR(4), IN p_qty INT ) BEGIN DECLARE v_stok INT; SELECT stok INTO v_stok FROM produk WHERE kodeproduk = p_kd; -- Melempar Pesan Error jika stok tidak mencukupi IF v_stok < p_qty THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Transaksi Dibatalkan: Stok barang di toko tidak mencukupi!'; END IF; UPDATE produk SET stok = stok - p_qty WHERE kodeproduk = p_kd; END;
RESPON Pesan Error ke Pengguna

Saat stok tidak mencukupi, perintah SIGNAL SQLSTATE '45000' membatalkan proses dan mengirim pesan kesalahan yang jelas:

ERROR 1644 (45000): Transaksi Dibatalkan: Stok barang di toko tidak mencukupi!
DECLARE EXIT HANDLER FOR SQLEXCEPTION:

Jika terjadi error tak terduga (misal tabel terkunci atau tipe data salah), handler ini otomatis memicu ROLLBACK agar data nota atau stok tidak tersimpan separuh jalan.

Unduh Skrip SQL & Import Database Minimarket

Sebelum memulai pengujian fungsi, prosedur, dan cursor, siapkan database minimarket_db (5 tabel 3NF + data transaksi awal) di server MySQL lokal Anda:

FILE Berkas DDL & DML (minimarket_db.sql)

Skrip SQL ini memuat pembuatan database, skema 5 tabel fisik (KASIR, CUSTOMER, PRODUK, NOTA, ITEMNOTA) dengan batasan integritas penuh (CHECK, FK CASCADE), serta 16 baris data transaksi awal.

Cara Import di MySQL Lokal:
• Terminal CLI: mysql -u root -p < minimarket_db.sql
• phpMyAdmin: Buka tab Import → Pilih file → Klik Go
• Workbench / DBeaver: Buka file SQL → Execute (Ctrl+Shift+Enter)
PREVIEW DDL: MINIMARKET_DB.SQL
-- Skrip Basis Data Minimarket (3NF Kelompok 7) CREATE DATABASE IF NOT EXISTS minimarket_db; USE minimarket_db; CREATE TABLE kasir ( KodeKasir CHAR(3) PRIMARY KEY, NamaKasir VARCHAR(30) NOT NULL, Pass CHAR(6) NOT NULL CHECK (CHAR_LENGTH(Pass) = 6) ); CREATE TABLE customer ( KodeCus CHAR(5) PRIMARY KEY, NamaCus VARCHAR(50) NOT NULL, TglLahir DATE NULL, JenKelCus CHAR(1) CHECK (JenKelCus IN ('L','P')), AlmtCus VARCHAR(100) DEFAULT 'Yogyakarta', HPCus VARCHAR(15) NULL, PointTerkumpul INT NOT NULL DEFAULT 0 CHECK (PointTerkumpul >= 0) ); CREATE TABLE produk ( KodeProduk CHAR(4) PRIMARY KEY, NamaProduk VARCHAR(50) NOT NULL, Harga INT NOT NULL CHECK (Harga >= 0), stok INT NOT NULL DEFAULT 0 CHECK (stok >= 0) ); CREATE TABLE nota ( Nonota CHAR(10) PRIMARY KEY, KodeKasir CHAR(3) NOT NULL, TglTran DATE NOT NULL, KodeCus CHAR(5) NOT NULL, FOREIGN KEY (KodeKasir) REFERENCES kasir(KodeKasir) ON UPDATE CASCADE, FOREIGN KEY (KodeCus) REFERENCES customer(KodeCus) ON UPDATE CASCADE ); CREATE TABLE itemnota ( Nonota CHAR(10) NOT NULL, KodeProduk CHAR(4) NOT NULL, banyak INT NOT NULL DEFAULT 1 CHECK (banyak >= 1), hargajual INT NOT NULL CHECK (hargajual >= 0), PRIMARY KEY (Nonota, KodeProduk), FOREIGN KEY (Nonota) REFERENCES nota(Nonota) ON UPDATE CASCADE ON DELETE CASCADE, FOREIGN KEY (KodeProduk) REFERENCES produk(KodeProduk) ON UPDATE CASCADE );

10 · TRANSAKSI TERPADU Integrasi Kasir, Customer, Nota, Item, & Produk

Studi Kasus: Prosedur Checkout Kasir Otomatis

Semua Komponen Bekerja Bersama: Prosedur ini memadukan UDF (fcGenerateNoNota), parameter OUT, validasi stok via SIGNAL 45000, serta transaksi atomik (START TRANSACTION ... COMMIT) dengan proteksi otomatis ROLLBACK lewat handler eksepsi.
PROCEDURE spCheckoutTransaksiBaru
CREATE PROCEDURE spCheckout( IN p_kasir CHAR(3), IN p_cus CHAR(5), IN p_produk CHAR(4), IN p_qty INT, OUT p_nonota CHAR(10), OUT p_total INT ) BEGIN DECLARE v_hrg INT; DECLARE v_stk INT; DECLARE v_poin INT; DECLARE EXIT HANDLER FOR SQLEXCEPTION BEGIN ROLLBACK; RESIGNAL; END; SELECT harga, stok INTO v_hrg, v_stk FROM produk WHERE kodeproduk = p_produk; IF v_stk < p_qty THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Stok Kurang'; END IF; SET p_nonota = fcGenerateNoNota(CURRENT_DATE()); SET p_total = v_hrg * p_qty; SET v_poin = FLOOR(p_total / 10000); START TRANSACTION; INSERT INTO nota VALUES (p_nonota, p_kasir, CURRENT_DATE(), p_cus); INSERT INTO itemnota VALUES (p_nonota, p_produk, p_qty, v_hrg); UPDATE produk SET stok = stok - p_qty WHERE kodeproduk = p_produk; IF p_cus <> 'M0000' AND v_poin > 0 THEN UPDATE customer SET pointterkumpul = pointterkumpul + v_poin WHERE kodecus = p_cus; END IF; COMMIT; END;

11 · TUGAS PRAKTIKUM 10 Soal Latihan Mandiri 4 Tingkat Kesulitan

Lembar Tantangan Praktikum Mahasiswa

Pilihlah tingkatan tantangan untuk melihat rincian soal tugas yang bersih dari jawaban bagi praktikan:

Soal 1 (UDF Evaluasi Persediaan Stok):

Buatlah UDF fcCekStatusStok(kd) yang mengembalikan: 'KOSONG' jika stok = 0, 'KRITIS' jika 1 s.d. 5, dan 'TERSEDIA (X Unit)' jika > 5. Uji dengan kueri SELECT pada tabel produk.

Soal 2 (UDF Klasifikasi Member Loyal):

Buatlah UDF fcLevelLoyalitas(poin) yang mengembalikan tingkat membership: 'PLATINUM' (≥ 100), 'GOLD' (50-99), 'SILVER' (20-49), dan 'BRONZE' (< 20).

Soal 3 (UDF Pemformatan Teks Rupiah):

Buatlah UDF fcFormatRupiah(nominal) yang mengubah angka integer menjadi format string mata uang Indonesia dengan awalan 'Rp. ' dan pemisah ribuan titik (contoh: 15000 -> 'Rp. 15.000').

SOLUSI SQL: SOAL 1 (fcCekStatusStok)
DELIMITER $$ CREATE FUNCTION fcCekStatusStok(p_kodeproduk CHAR(4)) RETURNS VARCHAR(30) DETERMINISTIC READS SQL DATA BEGIN DECLARE v_stok INT; DECLARE v_status VARCHAR(30); SELECT stok INTO v_stok FROM produk WHERE kodeproduk = p_kodeproduk; IF v_stok IS NULL THEN SET v_status = 'PRODUK TIDAK ADA'; ELSEIF v_stok = 0 THEN SET v_status = 'KOSONG'; ELSEIF v_stok <= 5 THEN SET v_status = 'KRITIS'; ELSE SET v_status = CONCAT('TERSEDIA (', v_stok, ' Unit)'); END IF; RETURN v_status; END$$ DELIMITER ; -- Pengujian: SELECT kodeproduk, namaproduk, stok, fcCekStatusStok(kodeproduk) AS status_stok FROM produk;
ANALISIS Penjelasan Logika & Output

Fungsi membaca data kolom stok dari tabel produk menggunakan klausa SELECT INTO dan mengevaluasi ambang batas unit menggunakan struktur kondisional IF-ELSEIF-ELSE.
